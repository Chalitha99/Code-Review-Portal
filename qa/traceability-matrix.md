# Traceability matrix

One row per spec section from SPL/OPS/FO-001 §1.5 through §2.19.3, mapping to
the manual test case IDs in [`test-cases/`](./test-cases/) that cover it and,
where one exists, the automated spec file already exercising the same
behaviour. Sections with no manual test case ID reconcile back to
[`gap-register.md`](./gap-register.md) — check there before treating an empty
row as a hole in coverage.

Manual cases are grouped per spec section; a case with `—` as its spec ref in
its own file (route/session behaviour, an inverse gap, an app-only addition)
is listed here under the section it is most closely associated with, or
omitted if it doesn't map to any spec section at all (see the gap register's
Section B).

## Reconciliation

Every row above with `—` in the "Manual test case IDs" column, and every row
noting "wording differs" or "partially missing," is explained in
[`gap-register.md`](./gap-register.md) — either Section A (no implementation
to test) or Section C (implemented, but the spec's exact wording doesn't
match). No spec section from §1.5 through §2.19.3 was silently dropped: check
here first if a section seems to be missing, then the gap register.
