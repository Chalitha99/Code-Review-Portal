# TC-REV-history — Review History Tab Page

Covers spec 2.10: 2.10.3.1 (Review History field table, "View" RMB) and 2.10.2.2 (History Page, "Back" RMB). Scope is `/crp/reviewer/history` and navigating from it into the read-only Review Task page. Primary user: Hiruni Wijethilaka (hiruni.wijethilaka@sebsaworld.com), Reviewer, who must have at least one previously decided (Approved or Changes Requested) review in the seed data.

Implementation facts verified against source before writing this file:

- Review History reuses the same `ReviewQueuePage` component as Available Tasks / My Review Tasks (`src/portals/code-review/features/reviews/routes/ReviewQueuePage.tsx`, `variant="history"`), so its columns and filter bar are shared code, not a bespoke history screen.
- The filter bar actually rendered (`TaskFilterBar`, `showCycle={variant === 'history'}`) offers: a free-text **Search** field (Task ID / Title / CRIM ID / Customer), a **Status** dropdown, a **Priority** dropdown, and — **only on this tab** — a **Cycle** dropdown (options: All, Cycle 1, Cycle 2, Cycle 3+). This is narrower than spec 2.10.3.1's field table, which lists five separate dropdowns: Statuses, Priority, Developers, Customers, Cycles. **There is no Developers or Customers dropdown filter anywhere in the app** — Developer and Customer narrowing is only possible via the combined free-text Search box, and only Customer (not Developer) is matched by that search. This is flagged for the gap register.
- The "View" action (`reviews.history.view` = "View") appears in the rightmost column of each row and also fires on a row click (`onRowClick` is wired for the history variant), navigating to `/crp/reviewer/tasks/:taskId` — the same Review Task page used for active reviews, rendered read-only via `canDecideReview` returning false once a task is no longer assigned/editable by this reviewer.
- The page's "Back" control (`reviews.form.back` = "Back", `BackLink` in `ReviewTaskPage.tsx`) always returns to `ROUTES.reviewer.root`, i.e. **`/crp/reviewer` (Available Tasks tab)** — not the Review History tab. This contradicts spec 2.10.2.2.1's RMB Action: "Returns user to the Reviewer Dashboard with the Review History tab selected." The Back link is generic across all three queue variants (My Review Tasks, History) and does not remember which tab launched it. This mismatch is logged for the gap register; the test case below asserts the real behaviour.
