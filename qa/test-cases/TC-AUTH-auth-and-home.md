# TC-AUTH — Authentication and Home Page

Scope: spec sections 1.5 (Home Page / SSO), 2.1 Three Main Workspaces, 2.3 Home
Page (2.3.2.1 RMB Options, 2.3.3 Functional Logic FL 2.1-01 and FL 2.1-02).
Covers sign-in/sign-out, session persistence and expiry, the route guard's
deep-link behaviour, and the home page's role-gated workspace cards,
notification bell, and user chip. Login is mock email/password
(`src/mocks/handlers.ts`), not real SSO — FL 2.1-01's SSO clause is not
implemented; the login page's "Sign in with SEBSA" button is deliberately
inert (see TC-AUTH-008) and this is a known, accepted gap, not a defect.
Shared password for every seeded account is `Sebsa@2026`
(`src/mocks/data/credentials.json`). Users referenced: Janith Hasthanayake
(janith.hasthanayake@sebsaworld.com — Developer, Reviewer, Admin, active),
Nimal Perera (nimal.perera@sebsaworld.com — Reviewer, **isActive: false**),
Dheliya Kankanamge (dheliya.kankanamge@sebsaworld.com — **Developer only**,
active). Each case states whether a fresh reload (discarding the in-memory
mock DB) is required beforehand; sign-out alone does not reset the DB.
